# Original rental return and hold closeout

The rental desk keeps accepted commitments visible after a replacement plan or cancellation. The scoped supplier records a condition observation against the original unit, quote, delivery and plan. The producer then reviews the exact original authorization, accepted fee and remaining hold separately. A return observation never grants financial authority by itself.

An original $780 authorization and $480 accepted fee therefore produce a $300 review. The fee remains an expense. Closing the remaining authorization is neither a fee refund nor a replacement-rental payment. The new flow preserves original provider, request, plan, supplier and capability identities, and it never marks a later rental delivered, paid or ready.

The producer opens /rentals from the production navigation, disruption desk or wrap. The supplier sees only its own retained commitments in its existing dedicated client. Both surfaces label controlled evidence, show original references and condition history, and explain pending or unavailable provider state. First entry requests authorized access without claiming an unused session expired. Show control now derives its gate count from the displayed readiness list.

The server enforces the following boundaries:

- Return records bind the original accepted delivery and unit, exact supplier capability, observation time and prior inspection. A later correction preserves earlier damage history. Damage blocks a new closeout or invalidates unused approval.
- The preview is bound to the current production revision and immutable original terms. Approval uses the exact producer capability and fixed expiry. Another capability cannot renew or retry it.
- Existing core operations retain their original request identity. A new closeout requires fresh original order, authorization and capture reads, one exact accepted fee, no additional active captures/refunds, and an unchanged remaining amount. Current authority is checked again after those reads.
- An unknown outcome is read back through the original operation. A definite refusal or not-sent result can be explicitly retried only by the original current capability. Stopping authority preserves history and original-only reads.
- Release proof requires a corroborated original void and complete original amounts. Later adverse or unavailable reads withdraw current proof while preserving historical receipts. Database read sequences prevent an older late response from restoring superseded proof.

The browser retains canonical command bytes before submission and looks up the original receipt after uncertainty. Only confirmed receipt absence permits an explicit same-command retry. Capability changes, damaged storage, wrong receipts and late responses cannot replace or discard the original instruction. Dialogs preserve keyboard focus and avoid taking focus back after a newer user action.

Migrations 14 and 15 are additive. They add immutable return, approval, stop, command and read history, mutable progress, and a sequence for ordering original observations. Existing financial and supplier records are not rewritten. New legacy accepted-return submissions are directed to this separate review; old saved supplier receipts remain recoverable and previously dispatched operations retain readback.
