# Supplier disruptions and reviewed cancellation

A supplier can fail after a plan was approved or a rental was committed. The Disruption desk records that new source, withdraws unsupported readiness, and keeps the original plan, payment records, crew calls and supplier obligations available for review. A producer can evaluate the current options, review a support-only show or a full cancellation, and approve exact remedies against the original ticket captures.

This source unit has controlled local qualification. Its provider fixtures are simulated responses through the installed PayPal SDK; they do not establish new authentic PayPal receipts, physical equipment failures, real attendance or personal crew acknowledgment. Native root review, actual-provider qualification and deployment are separate. See the [local qualification receipt](evidence/supplier-disruption-local-qualification.json).

## Record a change before choosing its consequence

Reports name the exact offer revision and, when one exists, the original rental execution. They retain the reporting actor, observed time, reference and explanation. A supplier capability can report only its own enrolled units. Only that supplier can reconfirm availability; a producer cannot impersonate a supplier's reconfirmation. A declared delivery delay affects candidate delivery times. An unavailable unit or an interrupted commitment stays blocked until current supplier terms support a newly reviewed plan.

A report does not cancel a show, refund a ticket, void an authorization or prove that a physical inspection occurred. It withdraws unsupported clearance and marks an interrupted committed rental for attention. Supplier reporting remains available before a replacement plan or reservation exists.

The recovery assessment retains twelve alternatives: the three currently enrolled offers and four running-order families. Each alternative uses the real local Bryntum engine and the application's existing resource, qualification, rest, cost, curfew and approval constraints. The desk distinguishes a bounded search with no feasible candidate from alternatives whose evidence is still pending. It never claims that twelve alternatives exhaust every possible production. Changes to the working graph, scenario clock, approved plan or disruption sources invalidate the saved assessment.

## Review the program and original money separately

A producer chooses a support-only show or full cancellation only after a current assessment and an exact financial preview. The preview is read-only and binds the current revision, source, mode and integer-cent amounts. A changed source requires a new assessment and preview.

Full cancellation targets the original $35 admission and, for VIP tickets, the original $15 perk. A support-only review can approve an admission remedy from $0 through $35 per captured ticket and the canceled VIP perk. Previously verified refunds reduce those targets. Every new allocation names one original owned ticket, order and capture, its gross amount and the exact prior refund identities and amounts. Pending, external, unallocated, ambiguous or conflicting original money blocks approval instead of being treated as zero. A rehearsal with no verified captures shows zero money to refund.

For example, the controlled 80-ticket fixture has $3,370 gross original captures. If the 38 original $15 perk refunds have already completed, full cancellation creates $2,800 of new admission remedies. It retains the earlier $570 refund history. It does not refund $3,370 a second time.

Approval saves one immutable decision and its allocations, then commits durable work. Each original capture is dispatched independently under the existing payment core. The original approving actor, exact session, fixed expiry, reviewed plan and allocation must still authorize a new write. Fresh provider reads must match the original capture and approved prior refunds. A revoked session, changed allocation, extra refund, stop instruction or expiry prevents a new dispatch. An ambiguous write uses its original operation for readback; it cannot create a replacement payment identity. Explicit retry is available only for a proved refusal or a proved undispatched original instruction.

Stopping prevents unstarted remedies; it does not claim to undo a provider write. Reading existing work remains possible without extending its approval. Refund completion is imported only from verified original provider evidence. The local native review disables financial and model transports and labels that boundary.

## Keep crew and supplier obligations visible

The operating decision publishes an internal production notice. It does not claim to send an audience email or deliver a message to a real person. Canceled calls remain in personal and production schedules with an explicit canceled label and their original timing. Crew engagement, shift ends, rest requirements, strike and accepted supplier fees remain visible. A new support-only plan excludes the canceled headliner and perk work, but still requires current supplier terms, a fresh producer review, publication, personal readbacks and applicable execution clearance. The notice alone cannot issue GO. Full cancellation blocks every show cue and cannot be replaced by a later operating decision.

An interrupted uncaptured rental has a separate original-authorization cancellation review. It requires the original authorization and exact session authority, and cannot capture a fee as part of cancellation. An accepted rental retains its earned fee and uses attributed normal return inspection before residual hold closure. Cancellation does not turn an accepted rental into a rejected delivery or manufacture a return inspection.

The controlled suite covers accepted-rental return and residual closure before replacing that rental's operating plan. Returning and closing an older accepted rental after a different plan and quote have replaced it remains a follow-up integration boundary. Do not present a new plan as closing the old supplier obligation.

## Recover the exact instruction

The client saves the exact command, identity and request digest before sending. Lost responses expose an explicit original-receipt lookup. A confirmed missing receipt allows an explicit retry of the same saved command. There is no automatic resend. A changed production, different session, expired capability, unavailable local storage or mismatched receipt prevents the client from silently adopting or replacing the pending instruction.

Command receipts are available only to their original exact capability. A second session for the same person does not inherit the original command or its financial authority. Supplier and crew capabilities cannot approve cancellation money. The first-entry touring page also distinguishes a visitor who has never opened a rehearsal from an expired session with a retained pending command.

## Persistence and qualification

Migration 13 adds immutable encrypted disruption records, exact-session command receipts, immutable remedy allocations, remedy progress and stop records. It does not rewrite earlier rental, ticket, payment, crew or touring history. Stored operating decisions and published sheets carry an operating digest so that a new program decision invalidates outdated readbacks without erasing them.

The unit uses the existing `@fracture/paypal-core` 0.2.4 and installed APIMatic-generated `paypal` 2.29.0 SDK. It adds no alternative payment client, credential path or retry layer. Controlled SDK responses exercise actual serialization and the existing durable payment operation boundaries.

The local qualification completed 681 tests: 538 product and persistence checks plus 143 controlled SDK checks. Fifteen HTTP checks passed against the actual production server, including same-origin and scope rejection, concurrent exact-command recovery, supplier isolation, real engine evaluation, stale-source rejection, cancellation notices and preservation of all original native fixture histories and expiries. TypeScript checking and the production build passed.

Targeted commands are:

```sh
npm run test:disruptions
npm run test:disruptions:payments
```

The stage-14 full regression, HTTP, preparation and review-server scripts are restricted to their owned local database and port. Native preparation retains a fixed fixture manifest and resumes only those original identities; it must not be used to reset an existing review. Provider-disabled guards are loaded before runtime configuration. Actual provider and native evidence must be recorded separately from these controlled results.
