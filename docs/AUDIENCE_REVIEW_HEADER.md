# Native audience review form policy

The private local review chooser and recovery-control pages use `Referrer-Policy: same-origin`. Their password forms contain no key or capability in a URL. This lets a native same-origin POST retain its exact Origin header, which the wrapper still requires. A missing, null or foreign Origin remains forbidden, even with a correct private review key. Other routes retain the wrapper's original default. The compiled Next application overrides that default with its unchanged `strict-origin-when-cross-origin` policy; this successor does not alter product headers or its production build. Attendee capabilities remain URL fragments, which are excluded from HTTP referrers.

The original native submission was rejected with403 before a session query, cookie or audience instruction. The prior wrapper's `no-referrer` policy caused the native form Origin to serialize as null. This behavior follows the [Fetch Standard's Origin-header algorithm](https://fetch.spec.whatwg.org/#append-a-request-origin-header). The first failed receipt and a focused failing policy check remain preserved privately.

This successor changes only the unbundled local wrapper policy. It reuses the byte-identical qualified production build, original native fixture, database schema and fixed capabilities. It neither renews authority nor repeats fixture preparation. A read-only exact-listener check verifies the chooser policy, strict Origin/key denial, unchanged audience/attendee policies and unchanged original stored rows. Its first run retained a failed assumption that the wrapper default survived Next's headers; the corrected check asserts the existing compiled policy. Root's native browser submission is a separate acceptance step.
