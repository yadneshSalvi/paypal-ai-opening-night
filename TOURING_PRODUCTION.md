# Touring production desk

`/tour` is a source-aware planning library and a cross-production touring desk. `/tour/crew` is an exact-capability personal view. Planning records are additive to the current account: a new production receives a new identity, empty operational and commercial evidence, and its own calls, venue clocks, role allocations and stage plan. It cannot inherit payment approval, supplier acceptance, physical work, technical signoff or GO from the original show.

The library supports blank, explicitly fictional demo, frozen-template-derived and reviewed-source-imported productions. Template editions retain reusable roles, skills, dependencies, relative call windows, assumptions and provenance. Source admission uses an existing completed compiler result with its exact actor/session, source versions, extraction hashes and reviewed assumptions. Person identities become reusable role IDs; rates, credentials, provider resources and operational records are excluded. Source locators open the original document/unit through existing source authority. Revised and archived originals remain inspectable.

Tours retain venue-local wall clocks, IANA zones, offsets and exact UTC instants. DST gaps are refused and folds require an explicit occurrence. Travel duration, loading, unloading, availability and forecast costs have declared provenance. The evaluator checks all member shows for skills, source windows, venue access, curfew, dependencies, shared capacity, overlap, maximum duty and uninterrupted rest. Travel is duty. Unknown paths remain unknown. Shared work in another active itinerary prevents qualification until the producer includes that work in a complete checked tour; overlapping outside calls are also reported explicitly.

A comparison enumerates two to six declared alternatives. It retains failed and unknown alternatives beside potentially usable ones, shows each category independently, and records real Bryntum Gantt Enterprise engine input/output evidence. It makes no claim of globally optimal routing. Applying one alternative requires exact named reviews, current tour and production editions, source state, current roster qualifications and successful revalidation. The database transaction commits the changed editions and one immutable command receipt together. Gantt and Scheduler share a read-only project; Calendar projects the same canonical IDs and instants independently. Diagram, call list and native components share selection.

A swap begins with the assigned person's own capability. The named recipient separately accepts or declines; a producer separately approves after complete revalidation. Withdrawals remain in history. Reversal requires a new proposal by the current assignee. Personal views expose only the person's own calls and proposals. Readback digests bind the person's own role, call and exact times: changing another person's role on the same call does not invalidate an unaffected obligation. The stage map distinguishes illustrative, unreviewed and source-reviewed dimensions, preserves unknown locations, and displays actual current personal readback separately from pending technical readiness.

Every browser mutation saves a normalized, hashed, exact-session command before dispatch. Unknown outcomes survive reload. Recovery checks the original command; retries reuse its original UUID and unchanged content only after explicit review. Expired, revoked or changed sessions pause actions. Foreground actions restore focus only while their original view remains active; background reads never acquire focus. Native dialogs retain keyboard/Escape behavior. Source/build/private fixtures are separate from production deployment.

## Reproduce a controlled local review

Use a new independent checkout with Node 22, npm 10.9.8, the repository's pinned vendor archives, a valid Bryntum licence and PostgreSQL binaries. Do not reuse an existing application environment or database. The following local-only scripts reserve application port **4548**, PostgreSQL port **55551**, schema `tour_runtime`, and cookie `opening-night-tour-4548-session`.

1. Run `npm ci --ignore-scripts` in that checkout.
2. Supply `BRYNTUM_LICENSE_KEY` privately, then run `node scripts/qa/tour-provision-local.mjs`. `TOUR_PG_BIN` may identify the directory containing `initdb` and `pg_ctl`; the macOS default is `/opt/homebrew/bin`. Provisioning creates fresh random admin/app credentials, owner-only files and a loopback-only cluster. It refuses an existing environment, cluster path or listener. It never resets a failed cluster; inspect its retained intent and logs.
3. Run `npm run test:tour`, then `npm run qa:tour:prepare` once. Preparation retains original command identities and capability expiry. It refuses an already-ready fixture. An interrupted preparation can continue only from its retained intent with `--resume` after inspection.
4. Build with `node --import ./scripts/qa/tour-disabled-providers.mjs node_modules/next/dist/bin/next build`, then run `npm run qa:tour:serve`.
5. Open `http://127.0.0.1:4548/__tour_fixture`. Read the review key privately from `.artifacts/tour-native-4548/fixture.json`. The chooser selects the original Producer, Tom, Priya, Sam or independent empty account. It cannot extend expiry. Crew access uses a fragment capability, removes it from the address bar and omits cookies on requests.
6. Run `npm run qa:tour:http` for controlled HTTP qualification. It creates new test tenants and verifies that the native fixture's original records, root history and expiry remain unchanged.

The three-show sample includes Denver, Omaha and Chicago, a frozen template revision, four alternatives, an overnight rest deficit, an unknown rail source and an unapplied personal swap request. Additional blank, demo and source-imported examples demonstrate independent provenance. All availability, travel, forecast prices and people in the scenario are explicitly fictional. No real booking, model response, payment, consent, physical work or technical completion is claimed by the fixture.

The provider-disabled runtime guards fetch, Node HTTP/HTTPS and the installed Toolkit transport, clears provider keys before environment loading, and does not supply a runtime bypass through HTTP. Existing SDK integration tests that install their own controlled in-memory transports require their test-only mode; they do not qualify an actual provider. Runtime migration 12 adds encrypted library records, immutable editions, exact command receipts, readbacks and retained source bindings without rewriting previous show or financial tables.

## Qualification boundaries

`test:tour` exercises domain, real PostgreSQL, actual Bryntum node-engine, recovery and DOM focus contracts. DOM tests explicitly do not claim native browser rendering. Browser qualification must check the real Gantt/Scheduler project, Calendar date/zone behavior, stage and list selection, source locator drill-through, dialog focus/Escape, reload and interrupted-response recovery, and 390/360-pixel layouts. Deployment, hosted migration, actual model/payment/provider qualification and promotion are separate coordinated gates.

Supplier disruption/cancellation, actual-provider release, larger evaluations, dependency remediation and cold installation, real-phone/research evidence or disclosed absence, and the film remain required parts of the full product. This workstream does not waive them.
